## 1. Назначение

Этот документ переводит утверждённый визуальный постер в обязательную структуру реализации WinUI 3.

Он нужен, чтобы исключить повторение ошибочного подхода, при котором старый технический XAML только перекрашивается темой и акцентом. После утверждения mapping дальнейшая работа выполняется как **пересборка экранов**, а не как постепенная стилизация существующей технической формы.

До прямого утверждения этого документа:

- код экранов Live TV, EPG, Channels и Settings не изменяется;
- PR #16 остаётся Draft;
- существующий интерфейс не считается визуальным baseline;
- допускается сохранение уже работающих Core-моделей, плеера, EPG-индекса и хранилищ настроек.

## 2. Иерархия источников истины

При реализации используется следующий порядок приоритета:

1. **Утверждённый визуальный постер v0.1** — геометрия, композиция, визуальная иерархия, плотность, взаимное расположение зон и характер компонентов.

## 4. Общая оболочка приложения

## 4.1. Визуальная структура

Утверждённая оболочка состоит из:

- постоянной левой основной навигации;
- компактной верхней строки контекстных действий;
- единой рабочей области без огромного дублирующего заголовка;
- поверхностей с небольшим числом уровней вложенности;
- самостоятельной адаптивной компоновки каждого раздела.

### Основная навигация

Порядок разделов фиксирован:

1. Эфир;
2. Телепрограмма;
3. Архив;
4. Записи;
5. Каналы;
6. Настройки.

`Каналы` — полноценный раздел, а не диалог внутри Эфира.

### Нижняя зона навигации

Допускается компактная карточка быстрого доступа к Избранному либо статус источника, но не технический постоянно изменяющийся лог.

## 4.2. WinUI mapping

| Концепт | Реализация |
|---|---|
| Левая навигация | `NavigationView` с кастомизированным item template и фиксированной иерархией |
| Рабочая область | отдельный `ContentPresenter`/host, а не набор одновременно существующих Grid с Visibility |
| Верхние действия | `EfironTopCommandBar`, адаптивный набор команд текущего раздела |
| Заголовок окна | extended title bar, использующий тему Efiron |
| Активный раздел | акцентная подложка + отдельный индикатор, не только изменение цвета текста |
| Compact pane | иконки с tooltip/AutomationProperties и корректным focus state |

## 4.3. Что удаляется из старой оболочки

- технический footer-статус как постоянный пункт NavigationView;
- огромный или дублирующий `HeaderTitle`;
- прямое переключение наборов старых Grid через `Visibility` как финальная архитектура;
- смешение настроек источника с ежедневными экранами.

## 6. Экран «Эфир — обычный режим»

## 6.1. Композиция из утверждённого постера

Wide layout содержит три основные колонки:

1. **Категории** — узкая левая колонка;
2. **Каналы** — средняя колонка;
3. **Плеер и программа** — доминирующая правая зона.

Под основной зоной расположен компактный ряд быстрых действий.

### Пропорции

При ширине рабочей области около 1280 px:

- категории: ориентировочно `150–180 px`;
- каналы: ориентировочно `220–280 px`;
- плеер: всё оставшееся пространство;
- внешние зазоры: `8–12 px`, без тяжёлых вложенных рамок.

Конкретная ширина уточняется адаптивным измерением, но визуальное соотношение с постером сохраняется.

## 6.2. Категории

Порядок сверху:

1. Избранное;
2. Все каналы;
3. категории провайдера/пользователя.

Требования:

- независимая вертикальная прокрутка;
- выбранная категория использует акцентную подложку;
- иконка и текст имеют единую визуальную массу;
- категория не оформляется как технический ComboBox;
- поиск не встроен внутрь каждой строки.

## 6.3. Список каналов

Каждая строка содержит:

- эффективный номер;
- логотип/плейсхолдер;
- название канала;
- время и название текущей передачи;
- индикатор избранного;
- состояние Playing;
- при доступном месте — следующую передачу или вторичный статус.

Строка выбранного канала на постере имеет акцентную подложку. Играющий канал дополнительно получает независимый символ/индикатор.

### Запрещено

- показывать `group-title`, `tvg-id` или URL как основную вторичную строку;
- размещать режим нумерации над списком;
- показывать `Показывать скрытые` в обычном Эфире;
- добавлять квадратные технические кнопки редактора рядом с фильтром.

## 6.4. Плеер

Плеер занимает наибольшую площадь экрана.

На видео/overlay отображаются:

- логотип канала;
- текущее время;
- название канала;
- жанр/краткая информация;
- возрастной badge;
- временной диапазон текущей передачи;
- прогресс;
- LIVE/Archive status при необходимости.

Под видео — `Now & Next`:

- «Сейчас» визуально приоритетнее;
- «Далее» вторичен;
- описание ограничено по высоте;
- длинный текст не меняет высоту всей рабочей области.

## 6.5. Быстрые действия

Нижняя строка содержит контекстные действия:

- сменить канал/вернуть фокус в список;
- добавить/удалить из избранного;
- сведения о программе;
- архив;
- меню.

На desktop это кликабельные команды; для пульта они отражают hot actions. Текст и иконка используются вместе там, где место позволяет.

## 6.6. WinUI layout

```text
Grid LiveWideRoot
├─ Column 0: EfironCategoryRail
├─ Column 1: EfironChannelList
└─ Column 2: Grid PlayerWorkspace
   ├─ Row 0: EfironPlayerSurface
   ├─ Row 1: EfironNowNextPanel
   └─ Row 2: EfironContextActions
```

`VideoView` и MediaPlayer сохраняются; заменяется окружающая компоновка.

## 7. Экран «Эфир — компактный режим»

Компактный макет из постера является отдельной адаптивной композицией, а не уменьшенной копией Wide.

### Структура

- слева остаётся список каналов;
- категории переходят в кнопку/overlay;
- справа сверху — уменьшенный плеер;
- справа снизу — текущий канал, программа, прогресс и Next;
- быстрые действия остаются в нижней строке.

### Переключение layout

Используется `VisualStateManager` либо контролируемая смена layout host:

- `WideState`;
- `MediumState`;
- `CompactState`.

Не допускается сжатие трёх Wide-колонок до нечитаемого состояния.

## 8. EPG — представление «Канал»

## 8.1. Композиция

Экран состоит из:

1. компактной верхней панели;
2. горизонтального выбора даты;
3. списка передач слева;
4. деталей выбранной передачи справа.

### Верхняя панель

- назад/контекст канала;
- название выбранного канала;
- избранное;
- overflow;
- сегментированный переключатель `Канал / Сетка` в общей EPG-оболочке.

### Даты

На постере даты представлены горизонтальной полосой дней, а не одиночным техническим CalendarDatePicker.

Реализация:

- `ItemsRepeater`/горизонтальный список дат;
- выбранная дата — акцентная;
- «Сегодня» различимо;
- стрелки периода доступны клавиатуре и пульту.

## 8.2. Список передач

Строка содержит:

- время начала;
- название;
- вторичный статус/категорию по необходимости;
- LIVE/archive badge;
- прогресс для текущей передачи.

Состояния:

- прошедшая;
- текущая;
- будущая;
- выбранная;
- доступна в архиве.

`Selected` и `Current` визуально различаются.

## 8.3. Детали передачи

Правая панель:

- постер/плейсхолдер;
- название;
- время;
- описание;
- жанр/возраст;
- основное действие `Смотреть` либо `Смотреть в архиве`;
- дополнительные действия в overflow.

Панель не должна выглядеть пустой тяжёлой карточкой при отсутствии выбора.

## 9. EPG — многоканальная сетка

## 9.1. Сохраняемые функциональные правила

- таймлайн всегда занимает всю доступную ширину;
- отдельного zoom selector нет;
- названия каналов закреплены слева;
- текущий момент отмечен вертикальной линией;
- диапазон содержит до 50 каналов;
- внутри диапазона работает вертикальная прокрутка;
- доступен прямой переход между диапазонами;
- поиск и категории применяются до диапазонов.

## 9.2. Визуальное соответствие постеру

Верхняя панель содержит:

- категории;
- Избранное;
- предыдущий/следующий день;
- текущую дату;
- Сегодня;
- поиск;
- переключатель режима EPG.

Навигация диапазонов находится внизу сетки и выглядит как компактный pager, а не набор служебных полей.

### Строка канала

Использует тот же логотип, номер и типографику, что Live TV.

### Блок передачи

- текущая — акцентная;
- прошедшая — приглушённая;
- архивная — семантический маркер;
- выбранная — отдельный focus/selection state;
- границы сетки лёгкие, не одинаково контрастные на всех уровнях.

## 9.3. WinUI mapping

- закреплённый левый `ItemsRepeater/ListView` каналов;
- общий вертикальный scroll host;
- timeline rows как виртуализируемые/ограниченные элементы диапазона;
- time header и rows используют общий горизонтальный размер без пользовательского zoom;
- при выборе программы открывается details flyout/panel либо переход в Channel view с сохранением контекста.

## 10. Раздел «Каналы»

## 10.1. Композиция

Постер фиксирует двухзонную рабочую область:

1. слева — таблица/список каналов;
2. справа — редактор выбранного канала.

### Верхняя панель списка

- поиск;
- категории;
- `Показывать скрытые`;
- overflow массовых действий.

### Таблица

Колонки первого среза:

- номер;
- название;
- категория;
- эффективный номер;
- избранное;
- скрыт.

Поддерживаются single selection и подготовка к multi-select.

### Правая панель

- логотип/плейсхолдер;
- название в Efiron;
- категория;
- номер;
- добавить/удалить из избранного;
- скрыть/показать;
- сбросить изменения.

Опасное действие имеет отдельный красный стиль и не находится рядом с основным сохранением без визуального разделения.

## 10.2. Что заменяется

Полностью удаляется release-использование сырого `ContentDialog` для редактирования канала. Существующая логика overlay-хранилища переиспользуется.

## 11. Настройки → Источники

## 11.1. Общая структура

Настройки имеют внутреннюю левую навигацию:

- Общие;
- Источники;
- Плеер;
- Интерфейс;
- Управление;
- О программе.

Постер показывает `Источники` как выбранный раздел.

## 11.2. Источники

На одном экране располагаются две логические секции:

### Плейлист M3U

- URL;
- состояние;
- последнее обновление;
- количество каналов;
- `Обновить сейчас`;
- автообновление;
- период.

### Телепрограмма XMLTV

- URL;
- состояние;
- последнее обновление;
- количество событий/сопоставлений;
- `Обновить сейчас`;
- автообновление;
- период;

URL и кнопки загрузки полностью удаляются с экранов Live TV и EPG.

## 11.3. Настройки → Интерфейс

Текущая рабочая тема/акцент сохраняются как инфраструктура, но validation-card заменяется полноценным экраном:

- язык;
- системная/светлая/тёмная тема;
- акцент Windows;
- пресеты;
- пользовательский ColorPicker;
- компактный предпросмотр реальных компонентов.

## 12. Состояния компонентов

## 12.1. Канал

| Состояние | Визуальный контракт |
|---|---|
| Normal | нейтральная поверхность |
| Hover | лёгкое повышение поверхности, без скачка размера |
| Selected | акцентная подложка и явный focus/selection marker |
| Playing | независимый media/equalizer indicator |
| Favorite | золотая звезда, не заменяющая Selected |
| Hidden | приглушение + crossed-eye только в Channels |
| Error | семантический error marker, канал остаётся доступен для действий |

## 12.2. Передача

| Состояние | Визуальный контракт |
|---|---|
| Past | сниженный контраст |
| Current | акцент + прогресс + LIVE |
| Future | обычный контраст |
| Selected | отдельная рамка/focus, даже если событие Current |
| Archive | фиолетовый badge/marker |
| Unavailable | приглушение и отсутствие ложного действия Смотреть |

## 12.3. Управление

Каждый интерактивный элемент обязан иметь:

- Normal;
- Hover;
- Pressed;
- Selected/Checked;
- Focused;
- Disabled.

Фокус клавиатуры/пульта видим без зависимости только от оттенка фона.

---

## 13. Светлая тема и акценты

Утверждённый постер показывает тёмную тему. Светлая тема сохраняет:

- ту же геометрию;
- те же размеры;
- ту же информационную иерархию;
- те же компоненты и состояния.

Меняются только authored surface/text/stroke palette и параметры теней/контраста.

Акцент применяется к:

- выбранному разделу;
- выбранной категории;
- выбранному каналу;
- основному действию;
- текущей передаче/прогрессу;
- выбранной дате/режиму EPG;
- focus visual.

Семантические цвета остаются независимыми.

## 14. Системные состояния экранов

Каждый экран проектируется не только для заполненных данных.

### Обязательные состояния

- первая настройка;
- пустой каталог;
- загрузка;
- фоновое обновление;
- ошибка сети;
- повреждённый источник;
- отсутствие EPG;
- отсутствие XMLTV match;
- буферизация;
- ошибка воспроизведения;
- stale/offline data.

### Welcome-state

Live TV без плейлиста показывает:

- понятное объяснение;
- основное действие `Добавить плейлист`;
- вторичное действие `Открыть настройки`.

EPG без XMLTV показывает действие `Настроить телепрограмму`, а не поле URL.
